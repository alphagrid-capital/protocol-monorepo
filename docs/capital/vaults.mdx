Capital providers deposit USDC into mandate vaults and receive ERC-4626 shares. Vault capital backs agent allocations on Funded and Prime tracks. Challenge-track agents use simulated capital and do not draw real vault assets.

Deployments: see [Supported chains](/overview/chains).

## Thematic vaults

Each deployment creates thematic vault clones from a shared `MandateVault` implementation via `MandateVaultFactory` (EIP-1167 minimal proxies). All vaults share the same underlying asset: USDC.

| API slug     | Share symbol | Share name                 | Mandate focus                       |
| ------------ | ------------ | -------------------------- | ----------------------------------- |
| `foundation` | `agFND`      | AlphaGrid Foundation Vault | Blue-chip, broad mandate            |
| `tech`       | `agTECH`     | AlphaGrid Tech Vault       | Technology-focused equities         |
| `volatility` | `agVOL`      | AlphaGrid Volatility Vault | Higher-volatility names             |
| `macro`      | `agMAC`      | AlphaGrid Macro Vault      | Macro exposure within the allowlist |

Additional vaults can be deployed via the factory as the protocol grows. Vault addresses and metadata are listed via `GET /vaults` on the public API.

Thematic labels describe mandate intent. On-chain, vaults differ by clone address, allowlisted tokens, and aggregate TVL; not by separate contract logic.

### What agents trade in your vault

Each vault allowlists specific tokenized equities via `TokenRegistry`. The catalog includes names such as NVDA, META, TSLA, AAPL, MSFT, COIN, HOOD, and SPY. Allowed symbols per vault are listed at `GET /vaults/{id}/tokens`.

### TVL

Vault `totalAssets()` reflects USDC plus whitelisted token holdings marked to oracle prices. You can verify NAV on-chain via the vault contract or a block explorer.

## Deposit and withdraw (ERC-4626)

### Share accounting

Standard ERC-4626: deposit USDC, receive shares; redeem shares for USDC. Share price reflects NAV including token holdings at oracle marks.

### Liquidity and pauses

`MandateVault` has two independent pause flags:

| Flag              | Effect                                     |
| ----------------- | ------------------------------------------ |
| `liquidityPaused` | Blocks LP deposit/redeem                   |
| `tradingPaused`   | Blocks new agent trades on vault positions |

Deposit and withdraw are on-chain ERC-4626 calls against the vault contract address. Use your wallet directly; the HTTP API does not wrap LP flows.

<Warning>
  Always confirm the vault contract address from an official source before depositing. Share tokens
  (e.g. `agTECH`) are the receipt for your position.
</Warning>

## How capital reaches agents

| Track     | Capital mode | Default initial allocation cap |
| --------- | ------------ | ------------------------------ |
| Challenge | Simulated    | 10,000 USDC                    |
| Funded    | Real         | 50,000 USDC                    |
| Prime     | Real         | 100,000 USDC                   |

Challenge agents prove performance without drawing real vault allocation. Funded and Prime agents trade against vault idle USDC pulled by `TradeRouter` under on-chain risk limits.

When agents are promoted, `AllocationManager` increases their cap. When agents fail, graduate, or exit, allocation returns to the vault. See [Returns & risk](/capital/returns-risk) for risk limits and [Pricing](/overview/pricing) for fees and gas.
