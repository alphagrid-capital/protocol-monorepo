# AlphaGrid Tokenomics and Incentives

## 1. Purpose

This document defines the economic design of AlphaGrid: fees, incentives, capital flows, agent rewards, protocol revenue, staking, slashing, and possible token utility.

The goal is not to force a token prematurely. The goal is to make incentives coherent whether the MVP launches with or without a native token.

---

## 2. Economic Design Goals

AlphaGrid incentives should:

1. attract high-quality agent builders
2. reduce spam and low-effort agents
3. reward real performance
4. protect capital providers
5. generate sustainable protocol revenue
6. discourage reckless strategies
7. support progressive capital allocation
8. avoid Ponzi-like or purely emissions-driven behavior

---

## 3. Core Economic Participants

| Participant | Provides | Receives |
|---|---|---|
| Agent Builder | Agent, strategy, execution logic | Performance rewards, reputation, allocation access. |
| Capital Provider | Vault capital | Strategy returns, rewards, data access. |
| Protocol | Infrastructure, vaults, scoring, risk system | Fees, token value accrual if applicable. |
| Operator/Governance | Parameter management, risk oversight | Protocol fees, governance rights. |
| Agent | Autonomous trading activity | Allocation, ranking, reputation. |

---

## 4. Economic Flow Overview

```text
Agent Builder pays entry fee / stakes collateral
  ↓
Agent enters Challenge track
  ↓
Protocol assigns capped capital
  ↓
Agent trades
  ↓
Profits/losses are accounted
  ↓
Profits split between capital providers, agent builder, and protocol
  ↓
Good agents graduate into larger tracks
  ↓
Failed agents lose access, stake, or reputation
```

---

## 5. Entry Fees

### 5.1 Purpose

Entry fees reduce spam and create economic commitment.

### 5.2 Recommended MVP Model

Use a fixed entry fee for Challenge.

Example:

| Track | Entry Fee | Notes |
|---|---:|---|
| Challenge | Low fixed fee | Anti-spam and commitment. |
| Proving | Higher fee or graduation only | Not open to all by default. |
| Prime | No direct entry | Graduation only. |

### 5.3 Fee Routing Options

Entry fees can be routed to:

1. protocol treasury
2. reward pool
3. insurance/risk reserve
4. agent prize pool
5. burn mechanism if tokenized

### 5.4 Recommendation

For MVP:

```text
70% protocol treasury
20% challenge reward pool
10% insurance/risk reserve
```

This keeps the model simple while creating visible incentives.

---

## 6. Agent Stake

### 6.1 Purpose

Stake adds stronger skin in the game than a non-refundable fee.

### 6.2 Stake Use Cases

Stake can be:

- returned after clean completion
- partially slashed for minor rule violations
- fully slashed for malicious behavior
- used as sybil resistance
- used for higher-track eligibility

### 6.3 MVP Recommendation

Do not require complex slashing in MVP unless necessary.

Recommended staged approach:

1. MVP: fixed entry fee
2. V2: optional stake for higher allocations
3. V3: slashing for malicious actions or severe breaches

---

## 7. Capital Provider Incentives

Capital providers deposit into track-level vaults or later agent-level vaults.

### 7.1 Provider Returns

Capital providers receive:

- share of trading profits
- possible protocol/token rewards
- access to curated agent performance

### 7.2 Provider Risks

Capital providers bear:

- strategy losses
- smart contract risk
- execution risk
- oracle/scoring risk
- liquidity/withdrawal constraints

### 7.3 MVP Recommendation

Start with limited/capped capital and clear warnings.

Avoid presenting vaults as yield products. Present them as exposure to agent performance inside a risk-managed arena.

---

## 8. Agent Builder Rewards

Agent builders should be rewarded for profitable and compliant agents.

### 8.1 Performance Fee

Agent builder receives a percentage of net profits generated by their agent.

Example:

```text
Net profit split:
80% capital providers
15% agent builder
5% protocol
```

Alternative:

```text
75% capital providers
20% agent builder
5% protocol
```

### 8.2 Graduation Rewards

Agents that graduate may receive:

- larger allocation
- leaderboard badge
- reduced future entry fees
- share of challenge reward pool
- reputation score increase

### 8.3 Recommendation

Use allocation growth as the primary reward. Avoid overpaying token incentives before performance is proven.

---

## 9. Protocol Revenue

Possible revenue streams:

| Revenue Source | Description | MVP? |
|---|---|---:|
| Entry fees | Fees paid by agent builders | Yes |
| Performance fee | Share of agent-generated profits | Yes, if real capital |
| Vault management fee | Ongoing AUM-style fee | Later |
| Data/API fees | Access to performance datasets | Later |
| Listing/verification fee | Premium agent profile or verification | Later |
| Token fee capture | Utility-based token fee flow | Optional |

### Recommendation

MVP should use:

1. entry fees
2. protocol share of profits, if real capital is live

Avoid management fees early. They add friction before the product proves performance.

---

## 10. Token Utility Options

A native token is optional. If introduced, it should have real utility.

Possible utilities:

1. pay entry fees
2. agent staking
3. governance over tracks/rules
4. fee discounts
5. access to premium data
6. reward distribution
7. slashing collateral
8. protocol treasury alignment

### Bad Token Utility

Avoid token utility based only on:

- emissions farming
- vague governance
- forced payment when stablecoin would be better
- unsustainable APY incentives

---

## 11. Tokenless MVP Option

AlphaGrid can launch without a token.

Use:

- stablecoin entry fees
- stablecoin-denominated vaults
- off-chain points/reputation
- agent badges
- transparent PnL
- performance fee accounting

Benefits:

- simpler legal structure
- faster launch
- less speculative noise
- clearer product-market validation

Drawback:

- weaker community incentive engine
- less immediate crypto-native distribution

---

## 12. Tokenized Model Option

If token is used, recommended utility:

| Utility | Description |
|---|---|
| Agent stake | Agents stake token to enter higher tracks. |
| Fee payment | Entry fees can be paid in token. |
| Fee discount | Token holders receive reduced challenge fees. |
| Governance | Vote on new tracks, risk parameters, reward pools. |
| Data access | Premium analytics/API access. |
| Slashing | Malicious agents can lose stake. |

---

## 13. Incentive Alignment

### 13.1 Agent Builders

Should maximize:

- sustainable risk-adjusted performance
- compliance with track rules
- long-term reputation

Should not maximize:

- short-term luck
- excessive leverage
- metric gaming
- sybil entries

### 13.2 Capital Providers

Should allocate to:

- diversified tracks
- consistent agents
- risk-adjusted performers

Should not chase:

- highest raw return only
- new agents with no sample size
- strategies with hidden tail risk

### 13.3 Protocol

Should maximize:

- high-quality agent ecosystem
- safe capital growth
- trusted performance data
- long-term fee volume

Should not maximize:

- short-term TVL at the cost of risk
- inflated token rewards
- underpriced capital allocation

---

## 14. Slashing Model

### Slashable Behaviors

Potentially slashable:

- unauthorized execution
- attempt to bypass risk controls
- oracle manipulation attempt
- wash trading / self-dealing
- identity fraud
- repeated severe rule breaches

Non-slashable by default:

- normal trading loss
- underperformance
- market volatility
- low returns

### MVP Recommendation

In MVP, do not slash normal performance failures. Only remove allocation and mark failed.

Slashing can be introduced later for malicious behavior.

---

## 15. Reward Pools

Reward pools can incentivize top agents.

Possible pool sources:

- share of entry fees
- protocol treasury
- sponsor funds
- partner ecosystem incentives
- token emissions, if applicable

Reward criteria:

- top Alpha Score
- best risk-adjusted return
- cleanest compliance record
- most consistent performance
- best new agent

---

## 16. Recommended MVP Economic Model

MVP should use the simplest credible model:

1. Fixed Challenge entry fee
2. Track-level capital pool
3. Capped agent allocations
4. Agent builder performance share
5. Protocol performance fee
6. No native token required initially
7. Off-chain points/badges for reputation
8. No slashing except admin-level removal for abuse

Recommended MVP split if real profit exists:

```text
Capital providers: 80%
Agent builder: 15%
Protocol: 5%
```

Alternative more agent-friendly split:

```text
Capital providers: 75%
Agent builder: 20%
Protocol: 5%
```

## 17. Open Tokenomics Questions

1. Should AlphaGrid launch with a token or tokenless MVP?
2. Should entry fees be paid in stablecoins, native token, or both?
3. Should Challenge capital be funded by entry fees, treasury, vault deposits, or sponsors?
4. Should agent builders receive performance fees immediately or only after graduation?
5. Should token staking be required for Proving/Prime?
6. Should bad agents lose stake or only lose allocation?
7. Should capital providers allocate by track or by individual agent?
8. Should protocol fees accrue to treasury, token holders, or both?
