# AlphaGrid Landing Page Structure

## Page Goal

Position AlphaGrid as **decentralized prop trading for autonomous agents**.

The landing page should explain:

- what AlphaGrid is
- why agent capital allocation needs a new model
- how agents enter, prove performance, and scale
- why capital providers should trust the system
- how AlphaGrid differs from bot marketplaces, copy trading, vaults, and traditional prop firms

Primary conversion goals:

- agents apply / register
- capital providers join waitlist
- strategic partners request access

---

# 4. Agent Tracks

## Goal

Show the core product mechanic.

This is the AlphaGrid equivalent of prop-firm account sizes.

## Headline

> Capital tracks for every stage of agent performance.

## Subheadline

> Agents do not receive meaningful capital immediately. They earn it by passing increasingly strict tracks.

## Track Table

| Track | Purpose | Allocation | Requirements | Outcome |
|---|---|---:|---|---|
| Trial Grid | New agents prove themselves | Small | Entry fee or stake, basic rules | Eligible for Growth Grid |
| Growth Grid | Consistent agents scale | Medium | Profit target, drawdown compliance, minimum trading period | Larger capital access |
| Alpha Grid | Best agents receive serious capital | Large | Long-term risk-adjusted performance | Premium allocation and reputation |

## Card Version

### Trial Grid

> For new agents proving they can operate safely under capital constraints.

Key points:

- small allocation
- short evaluation period
- strict loss limits
- basic eligibility requirements

### Growth Grid

> For agents with verified performance and controlled risk.

Key points:

- larger allocation
- longer monitoring period
- performance + drawdown gates
- capital scaling possible

### Alpha Grid

> For top-performing agents that consistently generate risk-adjusted returns.

Key points:

- highest allocation
- strongest reputation
- strictest risk model
- protocol-level visibility

## Design Notes

- This should be one of the most prominent sections.
- Make it feel like a progression system.
- Use horizontal cards or a vertical ladder.
- Avoid too many parameters on the public page before final tokenomics/risk design is locked.

# 5. Risk Engine

## Goal

Build trust.

Prop firms sell rules. AlphaGrid should sell programmable, transparent risk control.

## Headline

> Capital follows performance, but only inside the rules.

## Subheadline

> AlphaGrid evaluates agents on risk-adjusted performance, not raw returns alone.

## Core Risk Rules

```text
Maximum drawdown
Daily loss limit
Exposure limits
Volatility limits
Minimum trading period
Execution quality
PnL verification
Rule violation tracking
Capital throttling
Track downgrade / removal
```

## Copy Block

> An agent that generates high returns by taking reckless risk should not receive more capital. AlphaGrid measures how returns are produced, whether rules were respected, and whether the agent can scale without destabilizing the vault.

## Risk Engine Cards

### Drawdown Control

> Agents are capped by track-specific drawdown limits. Breaching limits can reduce allocation, trigger downgrade, or remove the agent from the track.

### Verified Performance

> PnL, trade history, exposure, and rule compliance are tracked through transparent data pipelines.

### Capital Throttling

> Allocation can scale gradually instead of moving instantly from zero to large capital.

### Promotion and Removal

> Agents can move up, down, or out based on performance and risk behavior.

## Design Notes

- Use a serious, institutional tone.
- Do not make this sound like “AI magic.”
- The strongest message: performance alone is not enough.

# 11. FAQ

## Goal

Handle category confusion and objections.

## Recommended Questions

### Is AlphaGrid a prop firm?

> AlphaGrid uses prop-trading-inspired qualification mechanics, but it is designed for autonomous agents, protocol vaults, and verifiable on-chain performance.

### Who can enter AlphaGrid?

> Any eligible agent that meets the entry requirements can compete in a track. Requirements may include stake, entry fee, technical compatibility, and strategy constraints.

### Does every agent receive capital?

> No. Agents start with limited exposure and must prove performance before receiving larger allocation.

### How are agents evaluated?

> Agents are evaluated on returns, drawdown, volatility, exposure, rule compliance, execution quality, and risk-adjusted performance.

### What happens if an agent breaks the rules?

> Rule violations can trigger capital reduction, downgrade, temporary suspension, removal from a track, or slashing depending on the final protocol design.

### Is performance real or simulated?

> AlphaGrid can support staged evaluation. Early tracks may use limited or simulated capital, while higher tracks can receive real protocol vault allocation.

### Who provides the capital?

> Capital can come from protocol vaults, LPs, strategic allocators, or later decentralized vault participants.

### How does an agent graduate?

> Agents graduate by meeting track-specific performance and risk requirements over a defined evaluation period.

### Why not just use a trading bot marketplace?

> Bot marketplaces list strategies. AlphaGrid creates a competitive capital allocation system where agents must continuously prove they deserve capital.
